# Архитектура WorldGod

Документ для тех, кто будет менять код: как устроены данные, в каком порядке идёт тик,
почему интерфейс обновляется именно так и где добавлять новое.

```
┌────────────────────────────────────────────────────────────────────┐
│                        worldgod_app (eframe)                       │
│  app.rs ── hud/* ── map_view.rs ── state.rs ── textures.rs ── theme │
└───────────────┬───────────────────────────────┬────────────────────┘
                │ AppState (мир + камера)       │ RGBA-кадр → текстура
                ▼                               ▼
┌───────────────────────────────┐   ┌────────────────────────────────┐
│      worldgod_core            │   │      worldgod_render           │
│ Simulation ─ World            │──▶│ scene::render_scene(&sim, opts)│
│ Entity / Building / Nation    │   │ terrain_pass → sprite → png    │
│ ai / combat / pathfind        │   └────────────────────────────────┘
└───────────────────────────────┘                   ▲
                ▲                                   │
                └──── worldgod_preview (PNG-сцены) ──┘
```

Зависимости строго в одну сторону: `app → {core, render}`, `preview → {core, render}`,
`render → core`, `core → ∅`. Ядро не знает ни про `egui`, ни про пиксели — его можно
использовать в серверной симуляции или в тестах без окна.

## 1. Данные мира

### Тайл и рельеф

Тайл хранит ровно три числа:

```rust
pub struct Tile {
    pub elevation: u16,  // 0..1000, уровень моря — 320
    pub moisture: u8,    // 0..255
    pub variant: u8,     // 0..3, декоративный вариант
}
```

Тип рельефа **не хранится**, а выводится функцией `terrain_at(elevation, moisture)`.
Из этого следуют два полезных свойства:

* кисть может менять только высоту и влажность — рельеф пересчитается сам;
* берег, пляж, лес и горы всегда согласованы: нельзя получить «гору на уровне моря».

`World` держит плоский `Vec<Tile>`, счётчик суши `land_tiles` (обновляется при записи) и
`revision` — номер версии карты, по которому приложение понимает, что текстуру пора
перерисовать.

### Существа

```rust
pub struct Entity {
    pub id, species, pos, prev_pos,
    pub hp, hunger, age, kills,
    pub nation: Option<NationId>,
    pub intent: Intent,      // что делает прямо сейчас
    pub path: Vec<TilePos>,  // кэш маршрута
    pub move_timer, attack_timer, think_timer,
    pub variant, alive,
    // ...
}
```

`prev_pos` нужен для интерполяции движения: логика идёт на 10 Гц, а картинка — 60 Гц.

`Intent` — это состояние поведения, а не команда:

```rust
enum Intent {
    Idle,
    Wander { goal: TilePos },
    Chop { tile: TilePos },
    Forage { tile: TilePos },
    Work { building: BuildingId },
    Attack { target: EntityId },
    AttackBuilding { building: BuildingId },
    Flee { from: TilePos },
}
```

Смена намерения очищает путь (`Entity::assign`) — поэтому существо не «доезжает» по
старому маршруту к новой цели.

### Страны и постройки

`Nation` — агрегат: имя, цвет, столица, население, солдаты, дома, убийства, потери.
Население и дома пересчитываются каждый тик из фактических сущностей и построек
(`refresh_nations`), поэтому счётчики не могут «разъехаться» с миром.

`Building` — либо стройплощадка (`progress < work_required`), либо готовый объект.
Костёр ставится сразу готовым, дом требует 40 единиц работы, порт — 60.
У готового дома, костра и порта есть `hp`: воины воюющей страны ломают их до
руин (`collapse`), руины территорию не держат.

### Дипломатия

```rust
pub enum Relation { Peace, Alliance, War }
```

`Diplomacy` — квадратная матрица статусов `n × n` (страны нумеруются с единицы,
поэтому индекс пары — `(a-1)*n + (b-1)`). Матрица растёт при основании новой
страны и сохраняет прежние договорённости; запись симметрична.

Кто с кем враждует, решает `Simulation::hostile_views`:

* монстр против человека — всегда;
* человек против человека — только если их страны на войне;
* любой житель против лодки — если страны воюют;
* союзники не враждебны друг другу никогда, зато воин на союзе ищет монстра,
  который стоит рядом с жителем страны-союзника (`nearest_threat_to_allies`).

## 2. Тик симуляции

`Simulation::step` — один тик, 10 раз в секунду. Порядок фаз важен:

```
1. ai::think_all        — размышления (не каждый тик, со сдвигом по фазе)
2. move_pass            — шаг по маршруту (тоже с индивидуальной паузой)
3. combat::resolve      — удары по существам и постройкам, смерти
4. economy_pass         — старение, голод, работа/рубка/еда
5. finish_tick          — уборка трупов, рождения, территории, порты, статистика
```

Почему именно так:

* **мышление первым** — чтобы существо могло среагировать на угрозу до того, как
  сделает шаг;
* **бой до экономики** — погибшие в этом тике уже не рубят лес;
* **уборка в конце** — все индексы, собранные в начале тика, остаются валидными,
  потому что `entities.retain` выполняется последним (и только по флагу `alive`).

Инварианты, которые нельзя ломать:

1. Индексы сущностей валидны в течение всего тика — массив не меняет длину до
   `finish_tick`.
2. Мёртвое существо (`alive == false`) не двигается, не думает и не работает —
   все фазы начинаются с проверки.
3. `Simulation::speed == Paused` останавливает тик целиком, но не мешает интерфейсу.
4. Любое изменение рельефа ставит флаги `blocked_dirty` / `territory_dirty`; тяжёлые
   пересчёты (карта занятости, территории) выполняются один раз перед первым тиком,
   которому они нужны.

### Пути

`PathFinder` — A* по сетке с бюджетом раскрытий (1500 узлов на запрос). Проходимость
зависит от стихии вида: `find_path_for(Species::Boat, …)` ищет маршрут по воде,
остальные — по суше и без клеток, занятых домами. Если бюджет
исчерпан или путь не найден, используется `greedy_step`: шаг к цели по восьми
направлениям с проверкой проходимости. Если и это не помогло — существо ждёт
(`move_timer`), а не исчезает и не телепортируется.

### Территории

`rebuild_territory` собирает `Vec<u8>` длиной с карту: 0 — ничья земля, иначе id
страны. Владение ставят только готовые постоянные постройки: столица — радиус 9,
дом и порт — радиус 4; руины не держат ничего, поэтому после разрушения дома
пятно территории исчезает. Первая страна, дошедшая до тайла, забирает его (никаких споров и
переделов — это упрощение сознательное).

## 3. Кисти

Все инструменты, кроме дипломатии, — кисти над миром. Инструмент
`Tool::Diplomacy` устроен иначе: он не рисует, а вызывает
`Simulation::cycle_relation` для пары стран, выбранных двумя тапами
(`AppState::pick_nation_at`).

`brush::paint` — чистая функция над `World`:

```rust
pub fn paint(world: &mut World, config: ToolConfig, center: TilePos, rng: &mut Rng) -> u32
```

Возвращает число изменённых тайлов. Внутри — нормализованное по радиусу расстояние,
шум для «рваных» краёв и мягкий спад по краям, чтобы мазок не выглядел круглым
штампом. После основного прохода вода у новой суши опускается до шельфа: иначе берег
выглядит обрывом в бездну.

Спавн существ — отдельная ветка: кисть выбирает проходимые тайлы в радиусе и просит у
симуляции создать существо (`apply_tool`), поэтому правила «нельзя спавнить в воду»
и «нельзя в занятую клетку» живут в одном месте.

## 4. Рендер

`worldgod_render` не знает про GPU: он рисует в `Frame` (RGBA8, строки сверху вниз).
Порядок слоёв:

```
Frame::filled(BACKGROUND)
 ├── terrain_pass::draw   — тайл: цвет от рельефа, тень с северо-запада,
 │                          вода (глубина + волны по time), пена у берега,
 │                          детали (деревья, камни, трава, песок),
 │                          территории и их границы
 ├── sprite::draw_building — тень + «арт» из символов; стройка — пунктир + progress
 └── sprite::draw_entities — сортировка по (pos.y, id), интерполяция позиции,
                             тень, спрайт, подсветка выбранного
```

Спрайты описаны строками:

```rust
const HUMAN: [&str; 4] = [".o.", "###", ".#.", "#.#"];
```

`Painter` растягивает символ в квадрат `scale × scale`, поэтому спрайт остаётся
читаемым и на 1 пикселе на тайл, и на 12.

PNG пишется вручную (`png.rs`): хранилищные блоки deflate, CRC32 и Adler32 считаются
на месте. Это десятки строк кода вместо зависимости — файлы чуть больше, зато сборка
без сети и без C-библиотек.

### Связка с egui

```
Simulation + alpha + time
   → render_scene(px_per_tile = 3) → Frame
   → egui::ColorImage::from_rgba_unmultiplied
   → TextureHandle::set / load_texture(TextureOptions::NEAREST)
   → Painter::image(rect, uv)   // uv-кроп = панорама и зум
```

Текстура обновляется не чаще 30 раз в секунду (8 на паузе), а панорама и зум вообще не
пересчитывают мир — меняется только область выборки из той же текстуры. Если игрок
только что мазнул кистью, `state.texture_dirty` заставляет перерисовать немедленно.

Важное правило: `AppState` **не** получает `egui::Context`. Состояние только выставляет
флаг `texture_dirty`, а обновлением текстуры занимается `map_view` внутри кадра — так
состояние остаётся тестируемым без окна.

## 5. Интерфейс

Кадр приложения (`app::draw_ui`):

```
TopBottomPanel::top("hud_top")        чипы статистики, часы, скорость, настройки
TopBottomPanel::bottom("hud_tools")   лоток инструментов + радиус + строка статуса
TopBottomPanel::bottom("hud_selected") карточка существа (если что-то выбрано)
CentralPanel::default()               map_view: карта, жесты, кисть
Window "Настройки мира"               размер мира, справка, версия
```

Панели — это `TopBottomPanel`, а не `SidePanel`: на телефоне экран вытянут по вертикали,
и такие панели дают ровно ту плотность, что у системного Android-интерфейса.

Жесты (`map_view::handle_input`), порядок приоритетов:

1. два пальца → панорама + щипковый зум (и выход);
2. колесо / трекпад под курсором → зум или прокрутка;
3. ПКМ / СКМ → панорама;
4. ЛКМ / палец → кисть.

Кисть применяется с антидребезгом (`AppState::brush_tick`): при переходе на новый тайл —
сразу, в пределах одного тайла — не чаще 12 раз в секунду; спавн существ — не чаще
3 раз в секунду, чтобы не залить карту монстрами.

## 6. Как добавить новое

| Задача                       | Куда смотреть                                                                 |
| ---------------------------- | ----------------------------------------------------------------------------- |
| Новый рельеф                 | `terrain.rs` (пороги + `Terrain::ALL` + `COUNT`), `palette.rs` (цвет), `world.rs` (порог влажности) |
| Новый вид существа           | `species.rs` (`Species`, `STATS`), `sprite.rs` (арт), `ai.rs` (ветка поведения) |
| Новая постройка              | `building.rs` (`BuildingKind`, работа, жильё), `ai.rs` (когда строить), `sprite.rs` |
| Новый инструмент             | `brush.rs` (`Tool`, `ALL`, подсказки), `ui_icons.rs` (иконка), `state.rs` при необходимости |
| Новая панель                 | `hud/`, подключение в `app::draw_ui`                                          |
| Новое событие                | `events.rs` (`EventKind` + префикс), вызовы `sim.events.push(...)`             |

### Правила, которые сэкономили время

* **Одна функция — одно место изменения.** Кисти живут в `brush.rs`, а не «где-то в
  приложении»; иначе спавн из UI начинает расходиться со спавном из тестов.
* **`world` не знает про `entities`.** Всё, что нужно знать существу (проходимость,
  препятствия), спрашивает `Simulation::is_walkable`, а не `World` напрямую.
* **Не держать заимствование мира на время работы с UI.** Копируйте нужные поля
  (`EntityView`, `Stats`) и работайте с копией — иначе `&sim` и `&mut state`
  конфликтуют в замыканиях egui.
* **Тесты без окна.** Интерфейс тестируется через `egui::Context::default()` и
  `ctx.run(...)`, поэтому `cargo test --workspace` идёт в headless-CI.

## 7. Производительность

Ориентиры на среднем мире 256×192 (49 152 тайла):

* тик симуляции — доли миллисекунды при 50–200 существах (основная стоимость — поиск
  пути, он ограничен бюджетом);
* пересборка текстуры 768×576 — самая дорогая операция кадра (порядка нескольких
  миллисекунд) и выполняется не чаще 30 раз в секунду;
* панорама и зум бесплатны: это UV-кроп одной текстуры;
* память кадра: `256×192×3²×4` ≈ 1.8 МБ.

Если понадобится больше — следующий шаг не «оптимизировать всё», а рисовать текстуру
только для видимой области (обрезать буфер по `ViewTransform::visible_tiles`).
